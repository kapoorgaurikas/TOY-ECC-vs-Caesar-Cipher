Project objectives

  • Generate ECC public keys through scalar multiplication.
  • Demonstrate a toy EC-ElGamal-style encryption/decryption example.
  • Encrypt/decrypt text using Caesar shifts.
  • Compare exhaustive search and language-frequency scoring.
  • Recover a private scalar in a deliberately tiny key space.

What to observe

  • Caesar has only 26 possible shifts.
  • Language statistics can help identify the likely Caesar key.
  • The toy ECC subgroup has order 9, so scalars repeat modulo 9.
  • Small-key brute force is feasible here, unlike a properly sized real ECC key search.

4. Elliptic-curve encryption on secp256k1

ECIES-style teaching demonstration. The receiver keeps secret d and publishes Q = dG. The sender chooses a fresh nonce r, sends R = rG, and derives a keystream from the shared point rQ = dR. The private-key range is deliberately restricted so the recovery experiment can run in a browser.

Important: This is an educational ECIES-style construction, not a production-ready encryption protocol. The restricted private-key range makes it insecure by design. Do not use it for real data.

5. Breaking Caesar with letter frequencies

A Caesar shift changes the labels of letters but preserves their frequency pattern. This experiment tests all 26 possible decryptions and ranks them using the chi-square distance between observed letter counts and a reference English frequency distribution. The lowest score is the statistical guess—not a guarantee.

How to interpret the result

Short messages often do not contain enough letters for stable frequency estimates. Longer messages usually provide more evidence, but the result can still be wrong if the text is atypical or the reference language model is mismatched. Exhaustive search always produces all 26 candidates; statistics helps rank them.

6. Recovering a restricted secp256k1 private key

The attacker knows the curve, base point G, and public key Q. With a deliberately small private-key range, the attacker can test candidate scalars until dG = Q. This experiment compares ordinary brute force with baby-step giant-step (BSGS), which reduces the number of group operations from roughly O(n) to O(√n).

Generate a target public key by running either attack.

What this demonstrates

  • The key is recoverable because its allowed range is intentionally small—not because the public key is secret.
  • Brute force requires up to n candidate multiplications; BSGS requires approximately √n stored/search steps, at the cost of memory.
  • For a properly generated 256-bit private scalar, exhaustive search is not practical; BSGS still requires on the order of 2¹²⁸ operations and infeasible resources.
  • The restricted-key experiment is a teaching demonstration and must not be described as an attack that breaks properly configured secp256k1.
